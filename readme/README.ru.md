# CoreDeck

[![CI](https://github.com/snakex21/CoreDeck/actions/workflows/ci.yml/badge.svg)](https://github.com/snakex21/CoreDeck/actions/workflows/ci.yml) [![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](../LICENSE) [![Platform](https://img.shields.io/badge/platform-Windows%2010%2F11-0078D6)](#сборка)

Портативный набор инструментов для Windows, помогающий упорядочить программы, драйверы, установщики, системные твики, профили установки и локальную документацию. Версия **2.4.0** · изменения: [CHANGELOG.md](../CHANGELOG.md).

Репозиторий — это чистая отправная точка. В нём нет программ, установщиков, приватных ссылок и данных автора. При первом запуске приложение создаёт пустые файлы в папке `data`; содержимое добавляется на экране **Управление**.

## Возможности

- **Каталог** — собственный каталог программ и установщиков, варианты программ и профили установки, отдельные страницы для драйверов и настроек программ, собственные HTML-страницы.
- **Запуск** — EXE, MSI, BAT, CMD и PowerShell. У портативных программ и инструментов есть кнопка **▶ Запустить**, и они запускаются прямо с флешки (как двойной щелчок в Проводнике, вместе с UAC): файл, указанный в каталоге, а если его нет — единственный подходящий `.exe` в папке (деинсталляторы, установщики и вспомогательные программы пропускаются, предпочтение отдаётся 64-битным). Если кандидатов несколько, CoreDeck спрашивает, какой запустить; если есть только архив или установщик, открывается папка.
- **Результаты установщиков** — коды выхода 1602 (отмена в установщике) и 1223 (отказ в UAC) выводят короткое «Установка отменена»; распространённые коды MSI (1603, 1618, 1619, 1638, 1639 и другие) получают понятные сообщения; 3010/1641 считаются успехом с пометкой о перезагрузке.
- **Диалоги внутри приложения** — никаких окон браузера `alert/confirm/prompt`; диалоги и уведомления работают с клавиатуры (Enter, Esc, Tab, возврат фокуса). Запуск установщика, скрипта или программы не требует подтверждения; подтверждение остаётся там, где что-то удаляется или изменяется система (удаление, твики, установка многих программ сразу).
- **KnowledgeBase** с проверкой ссылок и необязательный собственный сайт KnowledgeBase, который раздаётся из `data\KnowledgeBase\`.
- **Экспорт и импорт** данных.
- **Конфигуратор Windows** — твики и debloat с предпросмотром и подтверждением скрипта (см. [Безопасность](#безопасность)).
- **Журнал аудита** административных операций в `data/logs/audit.jsonl`.
- **Обновления** из релизов GitHub со стабильным и тестовым каналами, проверкой контрольных сумм и автоматическим откатом (см. [Обновления](#обновления)).
- **Интерфейс** — запоминаются размер и режим окна, тёмная и светлая темы, 30 языков интерфейса.

## Быстрый старт

Скачайте `CoreDeck-Portable.zip` из раздела **Releases** и распакуйте в любое место. Программа портативная и не требует установки: запустите `CoreDeck.exe`. При первом запуске рядом с exe создаётся папка `data\` (см. [Папка данных](#папка-данных)).

Чтобы обновить вручную, а не встроенным механизмом обновления: закройте CoreDeck и замените `CoreDeck.exe` (и `data\tools\disk-helper.exe`). Папка `data\` остаётся без изменений.

## Портативная структура

Предполагаемая структура на флешке — `<диск>\_Launcher\CoreDeck.exe`, а библиотека программ лежит в папках рядом с `_Launcher`. Пути в каталоге хранятся относительно exe (`../…`), а пути по умолчанию для импорта/экспорта, программ и драйверов определяются по диску, с которого запущен CoreDeck, поэтому проекту не нужен фиксированный путь и его можно перенести на другой диск или компьютер.

Если флешка получила другую букву, путь, сохранённый со старой буквой (например, `J:\…` после того как диск стал `L:`), ищется на диске, с которого запущен CoreDeck. При запуске такие пути в `programs.json`, `drivers.json` и `settings.json` один раз переписываются в относительную форму, при этом сохраняется копия `*.drive-<дата>.bak`.

## Папка данных

При первом запуске рядом с exe создаётся:

```text
data/
├── programs.json
├── drivers.json
├── settings.json
├── knowledge.json
├── tweaks.json
├── KnowledgeBase/     (необязательно: собственный сайт KnowledgeBase, /KnowledgeBase/)
├── icons/
├── user_pages/
├── webview/           (профиль WebView2: тема, язык, localStorage)
├── logs/
└── state/
```

**Приватные данные и один exe.** Все пользовательские данные читаются из `data\` рядом с `CoreDeck.exe`. Файлы, встроенные в exe (`cmd/launcher/web/data/*.json`), — это лишь пустые шаблоны, которые используются, когда файла в `data\` нет. Благодаря этому публичный `CoreDeck.exe` из Releases и приватная установка — один и тот же файл: приватный каталог, KnowledgeBase (`knowledge.json`) и сайт `data\KnowledgeBase\` находятся только в `data\`. Повреждённый файл в `data\` выводится как ошибка и не заменяется пустым шаблоном (следующее сохранение не перезапишет данные). Тесты следят за тем, чтобы приватные данные не попали во встроенные шаблоны или в `cmd/launcher/web/`.

## Обновления

Настройки → **Обновления**.

- **Каналы:** **Стабильный** (по умолчанию) и **Тестовый (предварительные версии)**.
- **Проверка:** необязательная проверка при запуске (не чаще раза в день) и кнопка **Проверить обновления**. Если есть более новая версия, окно внутри приложения показывает список изменений и кнопки **Обновить сейчас**, **Позже** и **Пропустить эту версию**.
- **Загрузка и проверка:** `CoreDeck-Portable.zip` скачивается из релиза GitHub `snakex21/CoreDeck`; его размер и SHA-256 сверяются с `SHA256SUMS.txt`. При несовпадении обновление прерывается и ничего не меняется.
- **Установка:** распаковываются только `CoreDeck.exe` и `data\tools\disk-helper.exe` — в промежуточную папку `.coredeck-update\` рядом с exe. Предыдущие исполняемые файлы сохраняются в `.coredeck-update\backup\<версия>\`, файлы заменяются переименованием старых в `.old`, и CoreDeck перезапускается.
- **Проверка работоспособности:** если новая версия не сообщит о корректном запуске в течение 60 секунд (или завершится), предыдущая версия автоматически восстанавливается и запускается снова. В настройках также есть кнопка **Восстановить предыдущую версию**.
- Работает в портативной структуре на USB (`<диск>\_Launcher\CoreDeck.exe`), для самого обновления не нужны права администратора, и ничего другого в `data\` не меняется.
- Без телеметрии: программа обращается только к API GitHub и к загрузке релиза.

## Сборка

Требования:

- Windows,
- Go 1.26 или новее (`go.mod` закрепляет toolchain `go1.26.11`, который `go` скачивает автоматически),
- компилятор C (MinGW gcc, нужен для WebView),
- по желанию `go-winres` (значок и сведения о версии в exe),
- Node.js,
- Python.

```bat
build.bat
```

Скрипт проверяет синтаксис JavaScript, запускает тесты Go и создаёт локальные `CoreDeck.exe` и `data`. Релизные сборки очищаются от лишней информации (`-trimpath -ldflags "-s -w"`), а `build.bat` записывает версию, название продукта и copyright в ресурсы Windows. Вариант с диагностической консолью:

```bat
build.bat debug
```

Инструменты разработчика WebView2 можно включить без отдельной сборки:

```bat
set COREDECK_WEBVIEW_DEBUG=1
CoreDeck.exe
```

`scripts\package.bat` собирает релизный архив `dist\CoreDeck-Portable.zip`.

## Тесты

```bat
go vet ./...
go test ./...
python -m unittest discover -s scripts
```

Тесты в браузере: запустите `python -m http.server 8765` в папке репозитория и откройте `http://127.0.0.1:8765/test/web/dialogs-smoke.html` (диалоги и уведомления, «PASS n/n» в заголовке) или `test/web/launcher-smoke.html` (лаунчер с заглушкой API).

CI (GitHub Actions) выполняет проверку синтаксиса JS, тесты Python, `go vet`, `go test -race`, `govulncheck` и сборку.

## Структура проекта

```text
cmd/launcher/         приложение и встроенный интерфейс
cmd/disk-helper/      вспомогательная программа для поиска диска
internal/             логика программы
scripts/              сборка и упаковка
test/                 тесты
```

Пустые данные по умолчанию, встроенные в exe, находятся в `cmd/launcher/web/data/`. Данные, создаваемые при работе с программой, локальны и игнорируются Git.

## Конфиденциальность

Программа работает локально. В репозитории нет пользовательского каталога, истории, приватных страниц, моделей ИИ и библиотеки установщиков. Единственное сетевое обращение самого CoreDeck — проверка и загрузка обновлений, при которых программа связывается только с API GitHub и официальными релизами проекта на GitHub.

## Безопасность

- Локальный сервер интерфейса слушает только `127.0.0.1`, отвечает только на заголовок `Host` `localhost:<port>` / `127.0.0.1:<port>` и не отправляет заголовков CORS (всё работает в пределах одного источника).
- Твики берутся из `data\tweaks.json` (импорт, редактирование) и выполняются с правами администратора. Перед первым запуском твика и после каждого изменения его команды конфигуратор показывает точный скрипт и просит подтверждения. Подтверждения (SHA-256 типа и команды) хранятся в `data\state\tweak_approvals.json`; программа выполняет команды из каталога, а не то, что прислала страница.
- Обновления устанавливаются только после того, как размер и SHA-256 совпадут с `SHA256SUMS.txt` (см. [Обновления](#обновления)).

## Профиль WebView2

Начиная с версии 2.3.1 профиль WebView2 (тема, язык, `localStorage`) хранится в `data\webview\` рядом с exe. Используется локальная пропатченная копия `webview_go` (`third_party/webview_go`, описана в `PATCHED.md`). При первом запуске существующий профиль из `%APPDATA%\CoreDeck.exe` копируется (без кэша); оригинал остаётся на месте, и его можно удалить вручную позже.
